# 项目检查与修复 — 2026-09-09

## 范围与证据

检查产品入口、四游戏管理服务、安装/维护状态机、启动进程生命周期、设置消费路径、运行资产定位、存储检查、核心命令执行、目录签名校验、下载/解包防护和 CI/分发脚本。此次是源码检查和本地回归，不等同于逐行证明全项目无缺陷，也不重复进行大包下载或游戏卸载。

全量 Swift 测试：438 项、57 套通过。真实卸载集成测试的授权环境变量明确清除；该用例未执行实际卸载，不能计为卸载验收。

## 本轮已修复

1. 卸载任务停止后，如果后台明确返回同游戏、同目录且 ready，并且本机仍有主程序，可解除未完成卸载标记恢复管理；未知或目录不符仍保留记录。提示先校验，不声称残余文件完整。
2. 重连之前核对监听进程的 WINEPREFIX 或专用目录内精确 HYP 可执行路径（Wine Windows 进程会清除导出的环境），拒绝把其他独立官方启动器当成我们的专用引擎。检查在后台线程运行，进程环境只在内存中判定，不进入诊断日志。
3. 下载事件监听增加页面级单次注册标记，避免每次重连累积回调。
4. 原神启动准备任务支持取消检查，避免停止后仍继续提交启动。
5. 其他游戏停止进程改为异步限时等待；启动失败时释放辅助进程和日志句柄，旧进程结束回调只处理对应运行。
6. 通用命令执行器同时排空 stdout/stderr，修复输出超过管道容量时先等待退出造成的死锁。增加双流大输出回归。
7. 其他三游戏接入 Metal HUD、原生全屏、启动后隐藏偏好；分辨率、图形档位、语言、120 FPS 的原神专属范围在设置中明确标出，不虚报全游戏适配。
8. 文件句柄泄漏测试只统计本测试目录，消除并行测试噪声，并将允许误差改为零。
9. 现场复现官方引擎冷启动时安装记录尚未加载却报目录冲突。维护入口增加初始化等待并独立提示未就绪；新安装也必须取得明确本地记录，不再把空响应当作未安装。
