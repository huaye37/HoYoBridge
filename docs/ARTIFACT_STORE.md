# 运行时产物缓存

## 当前范围

`ArtifactVerifier` 与 `ContentAddressedArtifactStore` 处理已经存在于本机的托管下载产物。它们不负责网络请求、重定向、断点续传、解压或安装。

运行时目录必须提供：固定 HTTPS 来源、预期字节数、SHA-256、许可证和已确认的再分发许可。目录校验失败时不会进入这一层。

## 缓存布局

```text
cache-root/
  .staging/<UUID>.part
  objects/sha256/cc/cccc...cccc
```

对象路径只来自规范化的小写 SHA-256，不使用 URL、版本名或外部文件名。

## 验证与提交

- 文件使用 `O_NOFOLLOW` 打开，并通过 `fstat` 要求普通文件。
- 缓存根、staging 和对象目录必须由当前用户拥有且权限严格为 `0700`。
- 本地源文件以 `O_EXCL` 创建唯一 staging，并按块复制；复制和校验都会检查任务取消。
- 以 1 MiB 分块读取，同时计算实际字节数和 SHA-256。
- 超出预期大小时立即停止；不足或摘要不匹配时拒绝。
- staging 与目标父目录必须位于同一文件系统。
- 提交前执行只读权限和 `fsync`。
- `RENAME_EXCL` 保证并发发布只有一个赢家，不覆盖现有对象。
- 已有正确对象直接复用；已有损坏对象、目录或符号链接时保留现场并报错。
- 取消或任意提交前失败都会删除本次唯一 staging；独占 rename 成功是提交点，此后不会因迟到的取消删除已发布对象。

## 下一阶段

网络层需要独立实现：TLS 验证、重定向域名策略、超时、取消、断点续传和下载上限。解压层需要独立防御绝对路径、`..`、符号链接、硬链接、设备文件和解压炸弹，并在完整 staging 验证后原子切换运行时版本。
