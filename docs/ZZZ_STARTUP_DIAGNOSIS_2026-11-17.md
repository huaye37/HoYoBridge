# 绝区零启动顺序回归调查（2026-11-17）

## 复现与更正

用户安装 0.1.16 后，国际服 3.3.0 再次在保护初始化阶段失败。启动日志已包含 `MGB_COMPAT timeout_fix=1`，但新 Player.log 仍显示 `MHYPBase` 崩溃，同期驱动错误为 `[4,1114,0]`。因此不能将此前加入超时参数视为完整修复。

本次同时检查新生成的 Player.log 和实际 `ZenlessZoneZero.exe` 进程，而不只检查启动包装进程。实测游戏已经产生 `Crash!!!` 后，包装进程依然存活。此前 40 秒的包装进程存活观察不能据此认定游戏启动成功。

## 控制变量对照

使用同一 NAS 游戏目录、同一固定 CrossOver 11.0-1 / DXMT 0.80、同一份账号环境的独立副本；没有修改游戏 DLL、hosts、代理或其他游戏配置。

| 配置 | 结果 |
| --- | --- |
| 原流程：先启动窗口辅助程序，再启动 Steam 兼容入口 | 约 16 秒产生崩溃日志 |
| 同上，仅改为 MSync | 约 16 秒产生同类崩溃 |
| 关闭原生适配，但仍先启动窗口辅助程序 | 约 18 秒产生同类崩溃 |
| 不启动窗口辅助程序，也不注入原生适配 | 超过 120 秒，无新崩溃记录 |
| 仅保留原生适配，不提前启动辅助程序 | 超过 120 秒，无新崩溃记录 |
| Steam 入口先启动，32 秒后启动辅助程序，两次 | 均超过 120 秒，无新崩溃记录，辅助程序完成样式处理 |
| 加回启动前注册表设置，不等待准备会话退出 | 约 19 秒再次产生同类崩溃 |
| 注册表设置完成后等待 `wineserver -w`，再先启动 Steam，延后辅助程序 | 超过 120 秒，无新崩溃记录 |

## 修正

- 仅绝区零国服和国际服在准备完成后，等待各自 Wine 会话自然结束（最多 20 秒）。不使用 `wineserver -k`，不结束其他游戏或下载服务。
- 让 Steam 兼容入口先启动；32 秒后才启动 Win32 窗口辅助程序，原生 AppKit 适配立即生效。
- 等待可取消；切换启动实例、停止游戏或进程结束后，不再启动过期辅助任务。辅助程序启动失败不终止已经运行的游戏。
- 日志增加 `fresh_session=1`、`window_helper_delay=32` 与延后辅助程序启动记录。

以上对照支持“准备会话与窗口辅助程序的启动顺序参与触发本机失败”的判断，但未反汇编证明保护模块内部的完整因果链。32 秒是本机验证过的初始化隔离窗口，不是上游承诺的所有设备统一阈值。

## 验收边界

完成独立环境启动对照、原环境启动观察及延后任务取消／替换、准备进程正常退出／错误／超时测试。没有自动登录或操作角色；登录后的持续游玩、国服及其他硬件仍需分别确认。不能把本次修正描述为解决所有 `MHYPBase` 问题。

上游也存在启用 timeout 后仍失败及运行时序相关的报告：[YAAGL #787](https://github.com/yaagl/yet-another-anime-game-launcher/issues/787)、[Proton #9883](https://github.com/ValveSoftware/Proton/issues/9883)。这些仅用于形成假设，本次改动依据为上述本机对照，而非直接套用其他平台结论。
